# คู่มือใช้งานและทดสอบ PCB Workflow Studio

## หน้าตาใหม่สำหรับใช้ส่วนตัว — 18 กันยายน 2026

- เริ่มที่ **ภาพรวม → ทำต่อ** ระบบเลือกขั้นถัดไปตามข้อมูลที่มี การเปิดผลที่สร้างแล้วไม่เรียก AI
- เมื่ออนุมัติโจทย์แล้ว ให้ค้นและเลือกชุดอุปกรณ์ จากนั้นดาวน์โหลดเอกสารและสร้างร่าง ผลเสร็จจะเปิดหน้าที่เกี่ยวข้องให้เอง
- หน้า **BOM และการเชื่อมต่อ** มีปุ่มสลับ **รายการอุปกรณ์ (BOM) / Pin-to-pin / Pin assignment**
- หน้า **Datasheet และหลักฐาน** พับชุดอุปกรณ์และเอกสารไว้ กดหัวข้อเพื่อเปิดดูหรือแก้เฉพาะรายการ
- ระหว่าง AI ทำงาน กด **หยุดงาน** บนแถบสถานะได้ งาน Codex CLI จะยุติโปรเซสของงานนั้น งานดาวน์โหลดหรือ API อาจต้องรอการเชื่อมต่อปัจจุบันคืนการควบคุมก่อนหยุด จะไม่เริ่มขั้นถัดไป
- หลังหยุดหรือเกิด timeout จะมี **ทำต่อจากขั้นที่ค้าง** ผลขั้นที่สำเร็จและบันทึกไว้ยังอยู่ ส่วนการเรียก AI ที่ยังไม่สำเร็จต้องเริ่มใหม่ จึงอาจใช้โทเคนเพิ่ม การหยุดไม่คืนโทเคนที่ใช้ไปแล้ว
- รีเฟรชหน้าเว็บขณะทำงานได้ ระบบจะกลับมาติดตามงานเดิมโดยไม่ส่งคำขอ AI ซ้ำ หากเซิร์ฟเวอร์ปิดไปต้องกดทำต่อเอง
- ลิงก์ PDF ที่เคยดาวน์โหลดไม่ผ่านจะถูกข้ามในการทำต่อ กด **ลองดาวน์โหลดเอกสารที่ขาดอีกครั้ง** เพื่อปลดรายการที่ข้ามและรันต่อ หรือเลือก **นำเข้า PDF เอง** หากหาเองเร็วกว่า
- กดเลือกชุดอุปกรณ์เดิมซ้ำจะไม่ล้าง Research หรือวงจร แต่การเปลี่ยนรุ่นจริงยังต้องสร้างและตรวจผลที่เกี่ยวข้องใหม่
- ดูโทเคน เวลา model / effort และค่าใช้จ่ายได้ที่หัวข้อพับ **การใช้ AI** ในหน้าภาพรวม

ร่างที่มีเลขขา/footprint ไม่ครบยังต้องเติมหลักฐานและตรวจ ไม่ใช่ไฟล์ PCB พร้อมผลิต ขั้นหลังตรวจร่างคือใช้ข้อมูลอ้างอิงทำ schematic / layout ใน EasyEDA แล้วนำไฟล์กลับมาตรวจ

คู่มือนี้อ้างอิง PCB Workflow Studio รุ่นที่ตรวจเมื่อ 17 กันยายน 2026

## 1. เปิดโปรแกรม

1. หากโปรแกรมเปิดค้างจากก่อนอัปเดต ให้ดับเบิลคลิก **Stop PCB Studio.cmd** ก่อน
2. ดับเบิลคลิก **Start PCB Studio.cmd**
3. เปิด http://127.0.0.1:8765 หากเบราว์เซอร์ไม่เปิดเอง
4. หากยังเห็นหน้าตาเดิม ให้กด Ctrl+F5

ผลที่ควรเห็น: หน้า PCB Workflow Studio มีรายการโปรเจกต์ แถบเมนู และปุ่มตั้งค่า AI provider

การปิดแท็บไม่หยุดโปรแกรม ใช้ Stop PCB Studio.cmd เมื่อเลิกใช้งาน ข้อมูลโปรเจกต์จะอยู่ต่อ แต่การตั้งค่า provider จากหน้าจอต้องตั้งใหม่หลังหยุด server

## 2. ทดสอบพื้นฐานแบบ Offline ก่อน

ใช้โปรเจกต์ทดลองแยกจากงานจริง ขั้นตอนนี้ไม่เรียก AI

1. เปิด **ตั้งค่า AI provider** เลือก **Offline** แล้วกด **ใช้การตั้งค่านี้**
2. กด **ลอง MCU Sensor Board 4-layer** ที่หน้าเริ่มต้น
3. ในหน้า Requirements เปิด **รายละเอียดที่กำหนดเอง / แก้ค่าที่เลือก** แล้วกด **ใส่ค่าทดลอง 4-layer**
4. กด **บันทึกบรีฟ / รายละเอียด** การใส่ค่าทดลองอย่างเดียวยังไม่บันทึก
5. ตรวจข้อมูลแล้วกดอนุมัติ Requirements ใส่ชื่อผู้ตรวจของคุณ และเหตุผลว่า **ทดสอบซอฟต์แวร์ด้วยข้อมูลตัวอย่าง ไม่ใช้ผลิตจริง**
6. กลับภาพรวม กด **รัน Research → BOM → Review**
7. เปิด **BOM และการเชื่อมต่อ** ตรวจว่ามีรายการอุปกรณ์และตารางสัญญาณ

ผลที่ควรเห็น:

- เกิดผลร่างและ Agent activity ที่ระบุ Offline
- จำนวน Codex/API calls ไม่เพิ่ม
- หากไม่มี datasheet ยืนยันเลขขา จะเห็นช่องว่างหรือ Unresolved และ Gate ถัดไปอาจถูกบล็อก นี่เป็นผลที่คาดไว้
- การได้ BOM ไม่ได้หมายความว่าระบบอนุมัติวงจรพร้อมผลิตแล้ว

## 3. ทดสอบ Codex แบบหนึ่งคำขอก่อน

แนะนำให้สร้างโปรเจกต์ตัวอย่างใหม่สำหรับทดสอบ AI เพราะการวิเคราะห์ Requirements จะล้างผลวงจรเดิมและถอนการอนุมัติที่เกี่ยวข้อง

1. เปิด **ตั้งค่า AI provider**
2. เลือก **Codex session**
3. ช่อง Model: เลือก model จากรายการ หรือเลือก **ใช้ค่าเริ่มต้นของ Codex**; หากใช้รุ่นอื่น เลือก **อื่น ๆ — กรอกชื่อเอง**
4. ช่อง Reasoning effort: เลือกค่า default ของ provider เพื่อเริ่มทดสอบ หรือระดับที่ model นั้นรองรับ
5. สำหรับ Codex ไม่ต้องกรอก API key หรือ API base URL
6. กด **ใช้การตั้งค่านี้** แล้วตรวจชื่อ model และ effort ที่แถบด้านบน
7. ไปหน้า Requirements ใส่โจทย์และค่าทดลอง แล้วกด **ให้ AI แนะนำแบบจากบรีฟ**
8. รอผลจนมีข้อความสำเร็จหรือข้อความผิดพลาด อย่ากดซ้ำระหว่างรอ
9. กลับภาพรวม ตรวจ **AI usage** และ **Agent activity**

ผลที่ควรเห็นเมื่อสำเร็จ:

- เห็นข้อเสนอแยกเป็น “อ่านจากบรีฟ” หรือ “AI แนะนำ” พร้อมเหตุผล โดยยังไม่เขียนทับค่าที่คุณเลือกไว้
- เกิดรายการ Requirements Agent ที่ provider เป็น `codex-cli:...`
- จำนวน calls เพิ่ม 1 เมื่อผลของการทำงานถูกบันทึกสำเร็จ
- มีเวลาในการทำงาน และมี input/output tokens หาก Codex ส่งข้อมูล usage กลับมา

การเลือก Codex ใน Settings หรือเห็นชื่อ model บนแถบด้านบนยังไม่ยืนยันว่าเชื่อมต่อสำเร็จ ต้องกดวิเคราะห์และได้รับผลจริงก่อน

กด **ใช่ ใช้ค่านี้** ทีละข้อ หรือ **ยอมรับข้อเสนอที่รอทั้งหมด** เพื่อบันทึกค่าที่ AI เสนอ หากไม่ชอบให้กด **ไม่ใช้ค่านี้** แล้วกดให้ AI แนะนำอีกครั้งเพื่อขอทางเลือกใหม่ จะส่งข้อเสนอที่ปฏิเสธกลับไปด้วย หากอยากแก้เองกด **แก้เอง** แล้วบันทึก รายละเอียดเชิงเทคนิคถูกพับไว้ และแสดงคำถามจำเป็นไม่เกิน 3 ข้อต่อรอบ

ค่าที่ AI แนะนำเป็นร่าง เช่น งบกระแสและกฎโรงงาน ยังต้องตรวจหลักฐานก่อนผลิต การยอมรับข้อเสนอไม่อนุมัติ Gate อัตโนมัติ

จากนั้นตอบคำถามจำเป็นที่เหลือ บันทึกและอนุมัติ Requirements แล้วจึงลอง **ค้นชิ้นส่วน / ทำต่อจากหลักฐาน** ตามขั้นตอนด้านล่าง

## 4. เลือก model และ effort

เปลี่ยนได้ใน Settings ก่อนเริ่มงานรอบถัดไป ผลรอบเก่ายังคงอยู่ในประวัติ

- Model เป็นเมนูเลือก พร้อมตัวเลือกใช้ค่าเริ่มต้นของ Codex และกรอกชื่อเอง รายการนี้ยังไม่ตรวจสอบสิทธิ์จากบัญชีอัตโนมัติ
- รายการ effort ในฟอร์มเป็นตัวเลือกทั่วไป บาง model อาจไม่รองรับทุกระดับ หากถูกปฏิเสธให้กลับไปใช้ default หรือระดับที่ model รองรับ
- ใน Codex mode การเลือกใช้ค่าเริ่มต้นของ Codex และ effort แบบ default จะอ่านค่าจากการตั้งค่า Codex ของเครื่อง
- ค่าที่แถบด้านบนเป็นค่าที่ตั้งสำหรับรอบถัดไป ดู Agent activity สำหรับข้อมูลของรอบที่ทำไปแล้ว

## 5. ค้นชิ้นส่วนและสร้างตารางการเชื่อมต่อ (รุ่นปรับปรุง)

1. หลังอนุมัติ Requirements เลือก Codex session แล้วกด **ค้นชิ้นส่วน / ทำต่อจากหลักฐาน**
2. ระบบค้นเว็บจริง แล้วเปิดหน้า Datasheet และหลักฐาน แสดง Reference, รุ่นสั่งซื้อ, ผู้ผลิต, package, เหตุผลและลิงก์ต้นทาง
3. กด **ใช้รุ่นนี้** ทีละรายการ หรือ **ใช้ชุดที่แนะนำทั้งหมด** หากไม่ต้องการบางรุ่น กด **ไม่ใช้รุ่นนี้** แล้ว **ค้นหาทางเลือกใหม่**
4. กด **ดาวน์โหลดเอกสารและสร้างร่าง** ระบบจะดาวน์โหลด PDF, เก็บต้นฉบับ, อ่านหน้าที่เกี่ยวข้อง และสร้าง BOM/Pin assignment/Connection table
5. ระหว่างรอแถบด้านบนจะแสดงขั้นตอนปัจจุบัน หากเอกสารบางชิ้นดาวน์โหลดไม่ได้ จะระบุรายการนั้นและยังเก็บเอกสารที่สำเร็จไว้
6. เลขขาที่อ่านจากหลักฐานได้จะแสดงเป็นร่างให้ตรวจ ไม่ต้องรอ Confirmed ก่อนจึงเห็นเลขขา แต่การผ่าน Gate ยังต้องตรวจต้นฉบับและยืนยัน
7. เมื่อยืนยันหลักฐานแล้วกด **สร้างจาก Research ปัจจุบัน** เพื่อสร้างวงจรใหม่จากข้อมูลเดิมโดยไม่ค้นเว็บหรืออ่าน PDF ซ้ำ
8. การตรวจตามกฎทำงานอัตโนมัติโดยไม่ใช้โทเคน หากต้องการความเห็น AI เพิ่ม ให้กด **ตรวจร่างด้วย AI เพิ่มเติม** ในหน้า Review

การค้นเว็บและอ่าน/สร้างร่างอาจใช้เวลาหลายนาที โดยค่าเริ่มต้นให้เวลาค้นหา 7 นาที และขั้นอื่น 5 นาที หากหมดเวลาระบบจะเก็บผลที่เสร็จแล้วและบันทึกการเรียกที่ล้มเหลวไว้ ให้กด **ทำต่อจากขั้นตอนที่เก็บไว้** หรือ **สร้าง BOM จาก Research ปัจจุบัน** แทนการเริ่มค้นหาใหม่ ค่าจำกัดนี้เปลี่ยนได้ด้วย `PCB_CODEX_TIMEOUT_SEARCH` และ `PCB_CODEX_TIMEOUT_STAGE` (วินาที, สูงสุด 15 นาที) ก่อนเปิดแอป

ระบบเก็บผลการค้นหา เอกสาร และผลอ่านเอกสารไว้ในโปรเจกต์ การกดทำต่อด้วยข้อมูลและ model/effort เดิมจะใช้ผลที่มีแล้ว ขั้นตอนที่ล้มเหลวจะเก็บผลขั้นก่อนหน้าไว้ให้ทำต่อ ไม่ควรกดค้นหาทางเลือกใหม่หากเพียงต้องการทำต่อจากเอกสารเดิม

ค่าแนะนำสำหรับเริ่มแบบประหยัด: ใน Settings กด **ใช้ค่าประหยัด: Terra / low** แล้ว **ใช้การตั้งค่านี้** ระบบไม่เปลี่ยน model ที่คุณตั้งไว้เองจนกดบันทึก

### ขอบเขตเอกสาร

- ดาวน์โหลดเฉพาะ HTTPS สาธารณะ สูงสุด 20 MB ต่อไฟล์ ตรวจทุก redirect และไม่เข้าถึงเครือข่ายภายใน
- ลิงก์ที่เป็นหน้าเว็บแทน PDF โดยตรงจะถูกรายงานเพื่อแก้ลิงก์/นำเข้าเอง ไม่ถือว่าผ่าน
- PDF ดาวน์โหลดอัตโนมัติรองรับสูงสุด 1,000 หน้า แต่เอกสารเกิน 80 หน้าอ่านเฉพาะ 60 หน้าแรกและ 15 หน้าสุดท้าย ต้นฉบับเก็บครบ
- ให้ความสำคัญกับตาราง pinout, ช่วงแรงดัน, package และวงจรตัวอย่าง ข้ามหน้าสารบัญ โดยจำกัด 3,500 ตัวอักษรต่อหน้าและบริบท 48,000 ตัวอักษรรวม การมีเอกสารไม่ได้หมายความว่าตรวจครบทั้งเล่ม
- ชื่อรุ่นและ package ในขั้นค้นหาเป็นข้อเสนอ ส่วน physical footprint/เลขขาของร่างวงจรต้องอ้างข้อเท็จจริงที่มีข้อความในเอกสารจริง ยังต้องตรวจความหมายและรุ่นอุปกรณ์กับต้นฉบับ
- ยังไม่มี OCR สำหรับ PDF สแกน; เลขหน้าอ้างอิงนับจากหน้าแรก PDF เป็น 1
- ค้นเว็บอัตโนมัติใช้ Codex session ส่วน API-compatible ยังใช้เอกสารที่นำเข้าเอง

## 6. อ่านสถิติรุ่นแก้ไข

- AI usage นับเฉพาะข้อมูลรุ่นใหม่ (telemetry_version=2) แยกแต่ละการเรียกจริง รวมรอบล้มเหลวที่ตัวเชื่อมบันทึกได้
- ถ้าไม่มีเอกสารและไม่ได้เรียก Research จะนับเป็น 0 ไม่คัดลอก tokens จาก Agent อื่น
- รายการเก่าที่อาจเคยลงซ้ำยังอยู่ในประวัติ แต่ไม่นำไปรวมยอดใหม่
- แสดงจำนวน web search events เพื่อยืนยันว่าขั้นค้นหามีการใช้เครื่องมือจริง
- Input/output tokens แสดงจาก provider; หากไม่ส่ง usage จะรายงานว่าบางรอบไม่มีข้อมูล
- Model ใช้ชื่อจากผลตอบกลับถ้ามี มิฉะนั้นใช้ชื่อที่ตั้งไว้; effort เป็นค่าที่ขอใช้
- เวลาเป็นเวลาของการเรียก AI ไม่รวมเวลาที่คนตรวจหรือเวลาทำงานทั้งหมด
- ค่า API เป็นประมาณการเฉพาะรุ่นที่มีตารางราคา ไม่ใช่ยอดเรียกเก็บจริง; โหมด Codex ไม่ตีราคาเป็นเงิน
- ยอดรายงานเป็นของ snapshot โปรเจกต์ที่เปิด ไม่ใช่ยอดบัญชีทั้งหมด และการชนกันของเวอร์ชันหรือการปิดโปรแกรมกลางงานอาจทำให้การบันทึกไม่ครบ

## 7. Export และทดสอบว่าเก็บข้อมูลอยู่จริง

1. เปิด **ประวัติและ Export**
2. กด **ดาวน์โหลดโปรเจกต์** เพื่อรับ ZIP
3. แตก ZIP และตรวจ `bom.csv`, `pin_connections.csv`, `agent_runs.json`, `usage_report.json` และ `parts_candidates.json`
4. `agent_runs.json` เก็บรายละเอียดรายรอบ ส่วน `usage_report.json` เป็นยอดรวมของ snapshot นั้น
5. หยุดโปรแกรมด้วย Stop PCB Studio.cmd แล้วเปิดใหม่ด้วย Start PCB Studio.cmd
6. เลือกโปรเจกต์เดิม ตรวจว่าข้อมูลและเวอร์ชันยังอยู่

ไฟล์ usage อยู่ใน ZIP แม้ยังไม่มีปุ่มดาวน์โหลดแยกรายไฟล์บนหน้า Export

## 8. ขอบเขตงานที่ทดลองได้

รุ่นนี้เป็นเว็บที่รันในเครื่อง มี Agent ตามขั้นตอน มีการตรวจหลักฐานและการอนุมัติ ยังไม่มี Discord bot, Telegram bot หรือการเชื่อม OpenClaw ที่พร้อมใช้ และยังไม่วาง schematic/routing ใน EasyEDA ให้อัตโนมัติ

หลังออกแบบใน EasyEDA เอง สามารถนำเข้า BOM, ภาพ, netlist/DRC รูปแบบกลาง และ Gerber ZIP เพื่อตรวจตามขอบเขตของตัวอ่านไฟล์ ตัวอย่างรูปแบบอยู่ใน `examples` ภาพใช้ให้คนตรวจ ส่วน Gerber ตรวจรายการไฟล์และข้อมูลพื้นฐาน ยังไม่ตรวจ geometry ของลายวงจร

## 9. เมื่อเจอปัญหา

| อาการ | วิธีตรวจต่อ |
|---|---|
| เปิดหน้าเว็บไม่ได้ | เปิด Start PCB Studio.cmd และตรวจว่าใช้พอร์ต 8765; ดู `data/server.log` |
| หน้าเก่า/ไม่มีตัวเลือกใหม่ | หยุดและเปิดโปรแกรมใหม่ แล้ว Ctrl+F5 |
| ปุ่มรันแผนกดไม่ได้ | ตรวจคำถามที่ยังขาด และอนุมัติ Requirements ก่อน |
| หา Codex ไม่พบ/ยังไม่ login | ตรวจ Codex CLI ในเครื่อง และใช้ `codex login status` ตรวจสถานะ |
| Codex timeout | ตัวเชื่อมรอได้ 120 วินาทีต่อครั้ง ลองบริบทสั้นลงหรือ effort ที่ต่ำลงซึ่ง model รองรับ |
| Model หรือ effort ถูกปฏิเสธ | กลับไปใช้ค่าเริ่มต้นของ Codex แล้วลองคำขอเดียว |
| ผลไม่ตรง schema / ส่งค่าบางช่องไม่ถูกต้อง | รุ่นแก้ไขส่ง output schema ให้ Codex โดยตรง และอ่าน JSON ที่มีกรอบโค้ดหรือข้อความหุ้มได้แล้ว หากยังผิดจะแสดงตำแหน่งช่องและชนิดข้อผิดพลาด ให้คัดลอกข้อความนั้นไว้ ผลที่ไม่ผ่านยังไม่ถูกบันทึก ไม่มีการเรียกซ้ำอัตโนมัติ |
| Tokens ไม่ปรากฏ | ตรวจ `agent_runs.json`; หากเป็น null แปลว่ายังไม่มี usage ที่อ่านได้ |
| Gate ไม่ผ่าน | อ่านเหตุผลในหน้าตรวจ/อนุมัติ แก้ข้อมูลและหลักฐานที่ระบุ |

หากต้องส่งผลทดสอบกลับมา ให้ระบุขั้นตอนที่กด โหมด/model/effort ข้อความผิดพลาด และสิ่งที่เกิดขึ้นจริง โดยไม่ต้องส่ง API key
